Look up every key in `config.toml`, including its type, default, and purpose. Every key is
optional, and you can run picturium without a config file. The
[Configuration & operations](/docs/configuration) page explains loading, cache sizing,
concurrency, CORS, and logs. Request-time signing, validators, cache busting, and capacity
are covered in the [Request model](/docs/request-model).

- To use an environment variable, uppercase the key, add the `PICTURIUM__` prefix, and put `__` between levels. For example, `output.encoder.avif.bitdepth` becomes `PICTURIUM__OUTPUT__ENCODER__AVIF__BITDEPTH`. Environment variables override the file.
- List values (`cors.allowed_origins`, `data.serve`, `output.format_priority`, `output.metadata`) are comma-separated in an environment variable.
- picturium validates values at startup. An out-of-range value or unknown key prevents the server from starting.
- The repository includes `config.toml.example` with the same defaults and inline comments.

Defaults for watermarks when `enabled` is true. Each key can be overridden with `watermark=…`, and `watermark=false` disables the mark for one request. An image takes priority over text.

## [output.quality_curves]

Each format has a quality curve based on image size. Images at or below `max_area` use
`max` quality; images at or above `min_area` use `min` quality. Sizes between them are
interpolated. The requested `q` level then shifts that value; `medium` and `auto` do not
apply an offset. All formats, including JXL, use the shared 1–100 scale here. `low`,
`high`, and `maximum` are offsets from −100 to 100.

## [output.encoder]

Encoder settings live under `output.encoder.<format>` for `jpeg`, `webp`, `png`, `avif`,
`jxl`, and `gif`. Each codec has its own `effort` scale; higher values usually encode more
slowly and produce smaller files.
