picturium can rasterise document pages through the normal image pipeline or return a
PDF or SVG document response. Use a raster [output format](/docs/output) when you want
to resize, crop, filter, or watermark pages; use `f=pdf` or `f=svg` when you want a
document rather than pixels.

```text
/manual.pdf?page=3&w=1200&f=webp
/slides.pptx?page=1-4&w=1600&f=webp
/diagram.svg?style=YmFja2dyb3VuZDp3aGl0ZQ==&f=pdf
/artwork.ai?f=svg
```

`f=svg` accepts only SVG and vector-art sources. `f=pdf` accepts PDF, SVG, Office,
and vector-art sources. Other pairings return `415`. Document responses bypass sizing,
cropping, filters, quality, metadata, watermarks, and raster output limits.

## Page selection

Use `page` or `pages` with one-based page numbers, comma-separated values, and ascending
ranges. A selection may expand to at most 1000 entries.

```text
/manual.pdf?page=3
/manual.pdf?pages=1,4-7,9&w=1200&f=webp
/manual.pdf?pages=2-4&f=pdf
```

`page=0`, descending ranges such as `7-4`, non-numeric values, and selections over the
1000-entry cap are invalid. `thumb=page:...` remains available for compatibility, but
the top-level parameter wins when both are present.

For raster output, picturium loads the selected pages and runs the same
[sizing](/docs/sizing), [cropping](/docs/cropping), [filters](/docs/filters), and
[watermarking](/docs/watermarking) stages on each. Only WebP and GIF can retain several
pages in one response; still-image formats return the first selected page. See
[Animation & video](/docs/animation) for multi-frame output controls.

With `f=pdf`, omitting `page` returns the complete PDF. A selection creates a PDF
containing the existing requested pages in document order; duplicates collapse and
out-of-range values are ignored when at least one requested page exists. If none exists,
the request returns `400`. PDF outlines pointing at removed pages are pruned.

## SVG

SVG has three distinct paths:

- `f=svg` returns an SVG source unchanged, or asks Inkscape for plain SVG from vector art.
- `f=pdf` converts the SVG into a one-page vector PDF.
- A raster format loads the SVG through libvips and applies the normal image pipeline.

`style` supplies base64-encoded CSS to the SVG renderer. `dpi` defaults to
`svg.load_dpi` (`72`). For raster output it controls load resolution; with `f=pdf` it
sets the physical page scale, so doubling the DPI halves the page dimensions in PDF
points while preserving the artwork.

libvips normally refuses SVG inputs larger than 10 MB. Set `svg.unlimited=true` only
for trusted large files. This guard belongs to the raster SVG loader; it is not a
general request-size limit.

SVG-to-PDF conversion accepts inline `data:` images. Local `<image href="...">` files
are ignored unless `svg.allow_local_resources=true`. When enabled, relative references
resolve beside the SVG but must remain inside `data.dir`; absolute paths and `..`
traversal outside it are rejected. Leave the option off when files in the data directory
belong to different tenants.

Referenced-file contents are deliberately absent from the generated-PDF cache key. Use
`force=true` after changing one; the forced response skips cache reads and HTTP validator
checks, regenerates the PDF, and replaces its cache entry. See
[Caching & force](/docs/request-model#caching--force); cache deployment details are in
[Configuration & operations](/docs/configuration#cache-tuning).

## PDF

A PDF raster request loads page 1 by default. Use `page` to choose pages and `dpi` to
override `pdf.load_dpi` (`72`). Higher DPI gives the raster pipeline more source pixels;
requested width and height still follow the regular [sizing rules](/docs/sizing).

```text
/report.pdf?page=2&dpi=144&w=1400&f=webp
/report.pdf?pages=1-3&w=1000&f=gif
/report.pdf?pages=2,5-7&f=pdf&download=extract.pdf
```

`f=pdf` without a page selection serves the original PDF. A subset is generated only
when pages are selected. Use `download=` for a `Content-Disposition` filename; other
response and cache headers follow [Output format & quality](/docs/output#delivery-download--original).

## Office documents

Office sources require the `soffice` executable. picturium converts them headlessly to
PDF, then either serves that PDF or rasterises its pages. A bare raster request converts
page 1 first for a faster response and starts the full conversion for later requests;
`f=pdf` without `page` needs the complete document.

`office.conversion_timeout` limits each conversion and defaults to 30 seconds. Completed
first-page and full-document conversions share the normal memory and disk cache. Use
`force=true` to regenerate and replace those cached intermediates.

## Vector art

AI, CDR, CMX, CDT, and EPS sources require the `inkscape` executable. picturium exports
the source's page area as PDF for raster or `f=pdf` output, and as plain SVG for
`f=svg`. These formats normally produce one page.

`vector.conversion_timeout` defaults to 30 seconds. PDF and SVG conversions use separate
cache entries; `force=true` regenerates and replaces them. Inkscape importer support
varies by the file's producer and version, so test representative assets before relying
on a format in production.

## Serving other files unchanged

An unsupported file type returns `415` unless its extension appears in `data.serve`.
The allowlist is case-insensitive and accepts entries with or without a leading dot.
`*` serves every unsupported file, including extensionless files, so explicit extensions
are safer.

```toml
[data]
serve = ["txt", "json", "zip"]
```

Allowlisted files are returned unchanged; transformation parameters do not apply.
`original=true` also returns any existing source unchanged and does not require its
extension in `data.serve`. For the complete parameter and status-code tables, see the
[Reference](/docs/reference).
