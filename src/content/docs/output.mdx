`f` / `format` picks the output format, and `q` / `quality` trades detail for file size.
Both are applied at the very end, after [sizing](/docs/sizing),
[cropping](/docs/cropping), [filters](/docs/filters) and
[watermarking](/docs/watermarking).

```text
/photo.png?w=1200&f=avif&q=high
/photo.png?w=1200&f=auto&q=72&meta=icc
```

## Format selection

Set `f` yourself whenever you need to know exactly what comes back:

`f=pdf` and `f=svg` give you a document rather than an encoded image, so sizing, filters,
quality, metadata and output limits don't apply. If the source can't produce the format
you asked for, you get `415`. [Documents & vectors](/docs/documents) covers which sources
work, page selection, conversion and the SVG safety settings.

Only WebP and GIF can hold several frames. JPEG, PNG, AVIF and JXL turn an animated source
into its first selected frame. See [Animation & video](/docs/animation) for frames,
timing, loops and video.

### Automatic selection

With `f=auto`, picturium walks through `output.format_priority` from left to right and
picks the first format whose media type appears in the request's `Accept` header. The
default order is:

```text
jxl → avif → webp → jpeg → png
```

If nothing matches, or there's no usable `Accept` header, you get WebP. GIF isn't in the
default list, so it's never picked automatically. Responses with an automatically chosen
format carry `Vary: Accept`; ones with an explicit format don't.

The matching is simple: it looks for literal media types like `image/avif`. Wildcards and
quality weights aren't interpreted, so clients using `f=auto` should list image types
explicitly (browsers already do).

`output.enable_avif`, `output.enable_webp` and `output.enable_jxl` exist in the
configuration but aren't used yet. They don't switch formats off, explicit or automatic.

## Quality

`q` takes `low`, `medium`, `high`, `maximum`, `auto`, or a number from `1` to `100`. The
default is `output.quality`, which is `medium`.

- A number goes straight to the encoder.
- `auto` and `medium` use the format's quality curve as-is.
- `low`, `high` and `maximum` add that format's offset to the curve, then clamp the
  result to `1–100`.

Named levels depend on image size. picturium measures the final image (for animations
and documents, a single frame or page). At `0.25 MP` or less it uses the curve's `max`, at
`8 MP` or more its `min`, and anything in between is interpolated.

<DataTable head={['format', ...curveCols]} rows={curves} cols={['k', 'd', 'd', 'd', 'd', 'd']} />

`min_area`, `max_area` and every value in the curves can be changed under
`output.quality_curves`. JXL uses the same `1–100` scale as the rest and converts it to a
distance internally. PNG switches to lossless encoding at quality `100` by default and
uses a palette below that. GIF has no quality setting of its own, so quality controls the
palette size, dithering and how much animation frames can be simplified.

```text
/hero.jpg?f=webp&q=medium
/icon.png?f=png&q=100
/gallery/photo.jpg?f=jxl&q=78
```

## Metadata

`meta` / `metadata` decides which metadata from the source survives in the output.
Separate several values with commas:

<p class="fmt">none · icc · exif · xmp · iptc · other · gainmap · all</p>

```text
/photo.jpg?f=jpeg&meta=icc,exif
/photo.jpg?f=webp&meta=none
```

The default comes from `output.metadata`, which is `none`. `all` keeps everything that's
supported. Not every format can store every kind of metadata, and document and original
responses ignore this setting.

## Output limits

`limit` / `limits` caps the output size in pixels, bytes, or both:

```text
/photo.jpg?limit=dimension:1200
/photo.jpg?limit=dimension:1200x800|size:500K
/photo.jpg?limit=dimension:x800|size:1.5MiB
```

<DataTable
  head={['Key', 'Value', 'Behaviour']}
  cols={['k', '', '']}
  rows={[
    ['dimension', 'N · WxH · Wx · xH', 'Scales the result down, keeping proportions, until it fits the given width and/or height.'],
    ['size', 'bytes · K/KB/KiB · M/MB/MiB · G/GB/GiB', 'Re-encodes at lower quality when the first encode is too big. Units are binary (1K = 1024 bytes).'],
  ]}
/>

Request limits replace the matching `output.max_width`, `output.max_height` and
`output.max_size` defaults. A side you don't mention still gets its configured limit; set
the config value to `0` to have no server-wide limit. Because a request can also raise
these limits, turn on [signed URLs](/docs/request-model#signed-urls) if you rely on them
to protect the server.

For a byte limit, picturium makes at most `output.max_size_attempts` extra attempts and
never goes below `output.max_size_min_quality`. It stops as soon as a result lands within
`output.max_size_threshold` percent under the target. If it can't get under the target,
you get the smallest attempt, even if it's still too big.

## Delivery: download & original

`download` adds `Content-Disposition: attachment`. Leave it empty and the filename is the
source name with the output's extension; give it a value and that's the filename.

```text
/photo.png?f=webp&download
/photo.png?f=webp&download=homepage-image.webp
```

The filename doesn't change the format. `f` still decides what's actually sent and its
`Content-Type`. Non-ASCII characters, quotes and backslashes in the name are replaced
with `_`.

`original=true` returns the source file untouched. Format negotiation, sizing, crop,
filters, [watermarking](/docs/watermarking), quality, metadata and limits are all
skipped. You can still combine it with `download`.

All aliases and defaults are listed in the [URL parameter reference](/docs/reference).
