Every transformation is a `GET` request. The path chooses a source beneath `data.dir`;
the query string describes the result. picturium verifies the URL, resolves the source,
parses the parameters, checks validators and generated caches, then either serves or
renders the response.

<RequestFlow />

The compact list of every parameter and alias is in the
[Quick reference](/docs/reference#url-parameters).

## URL grammar

```text
GET /<path-under-data.dir>?<name>=<value>&<name>=<value>
```

For example, with `data.dir = "data"`, this request reads
`data/catalog/chair.jpg`:

```text
/catalog/chair.jpg?w=1200&h=800&fit=cover&f=webp&q=high
```

- The URL never includes `data.dir`. picturium canonicalises the source and refuses a
  path that escapes the data directory.
- Parameter names and aliases are case-sensitive: `w` and `width` work; `W` does not.
  Named enum values are case-insensitive, so `fit=Contain` and `fit=contain` match.
- Most common parameters have a short alias, such as `w` / `width`, `h` / `height`,
  `f` / `format`, and `q` / `quality`.
- Grouped parameters join case-sensitive `key:value` parts with `|`, for example
  `crop=w:400|h:300|g:attention`.
- URL-encode user-provided paths, filenames, watermark text, and other free-form values.
  Their `&`, `=`, `|`, `#`, and percent-encoding must not be allowed to change the query.
- Unknown top-level parameters are ignored. Invalid values for known typed parameters
  are rejected with `400`, so use the [parameter index](/docs/reference#url-parameters)
  to catch spelling mistakes.

Transform order and parameter-specific rules live with [Sizing & layout](/docs/sizing),
[Cropping](/docs/cropping), [Filters & effects](/docs/filters),
[Watermarking](/docs/watermarking), and [Output format & quality](/docs/output).

## Signed URLs

URL signing is off by default. Enable it only with a strong secret:

```toml
[security]
signature_enabled = true
signature_secret = "replace-with-a-long-random-secret"
```

When enabled, every file request needs a lowercase `token` query parameter containing a
hex-encoded HMAC-SHA256 digest. The signed payload is the path without its leading slash,
followed by `?` and the exact raw query string with every `token=` pair removed:

```text
payload = "catalog/chair.jpg?w=1200&f=webp"
token   = hex(HMAC-SHA256(signature_secret, payload))

/catalog/chair.jpg?w=1200&f=webp&token=<token>
```

Preserve query order, repeated fields, separators, and percent-encoding between signing
and sending. If `token` is the only query parameter, the payload still ends in `?`.
The token itself is not part of the payload.

A missing, non-hex, or mismatched token returns `403 Invalid signature` with
`Cache-Control: no-store`. The root page, `/public/*`, and `/health` are separate routes
and are not signature-protected. Keep the secret server-side; never place it in browser
code. Generate a value with `openssl rand -hex 48`, and see the
[`[security]` config reference](/docs/config-keys#security) for the environment-variable
names.

## Caching & force

picturium has two distinct cache layers:

1. The browser or CDN caches the HTTP URL according to `cache.cache_control`.
2. picturium caches generated responses and conversion intermediates in its configured
   memory and disk tiers.

The server key is derived from the picturium version and resolved configuration, source
path, source modification time and size, effective parameters, and resolved output
format. It is not the literal request URL. Normal concurrent misses for the same key are
coalesced into one render.

Use the two cache-busting parameters for different jobs:

<DataTable

  cols={['k', '', '']}
  rows={[
    ['cache=<value>', 'Changes the URL, so it can create a new client or CDN entry.', 'Ignored when deriving the server key; the cached render and ETag stay the same.'],

  ]}
/>

`force=true` does not change the ETag because `force` is not part of the effective
parameters. For an unchanged raw or `original=true` response there is no generated entry
to replace; force only bypasses conditional validation and returns `no-store`.

Cache capacities, eviction, entry-size limits, and clearing the disk cache are covered in
[Configuration & operations](/docs/configuration#cache-tuning). Document conversion cache
behaviour is covered in [Documents & vectors](/docs/documents).

## HTTP caching

Successful responses normally use `cache.cache_control`, which defaults to:

```text
public, max-age=604800, must-revalidate
```

Generated responses include an `ETag` derived from the server cache key and a
`Last-Modified` value from the source file. Send either validator on the next request:

```http
If-None-Match: "6bc3a2a6683f12d4"
If-Modified-Since: Sat, 29 Aug 2026 12:00:00 GMT
```

If `If-None-Match` is present, it takes precedence over `If-Modified-Since`. A matching
ETag, an `If-None-Match: *`, or an unchanged source date returns `304` with an empty body.
`force=true` skips these checks.

Responses negotiated with `f=auto` include `Vary: Accept`; explicit formats do not.
Raw gzipped SVG responses use `Vary: Accept-Encoding`. See
[automatic format selection](/docs/output#automatic-selection) for the accepted media
types.

## Errors & fallback

`fallback` is another source path beneath `data.dir`, not a remote URL. It is tried only
when the requested source cannot be resolved:

```text
/catalog/missing.jpg?w=800&fallback=placeholders/product.jpg
```

The fallback goes through the same path-safety checks and then receives the original
request's transforms. It is not retried after a decode, conversion, rendering, or
encoding failure. Use it for known missing files, not as a general error handler.

Handler-generated `403`, `404`, `415`, `500`, and `503` responses use
`Cache-Control: no-store`. `original=true` is different from fallback: it requires the
requested source to exist, then serves it unchanged. See
[delivery and original responses](/docs/output#delivery-download--original).

## Health & capacity

`GET /health` returns the live worker and queue counters without requiring a signature:

```json
{
  "name": "picturium",
  "version": "2.0.0",
  "status": "healthy",
  "total_workers": 8,
  "available_workers": 6,
  "queue_size": 100,
  "available_queue_size": 100
}
```

`server.workers = 0` resolves to twice the available CPU count. Each transformation holds
one worker permit. A request may wait in one of `server.queue_size` queue slots; once all
workers and slots are occupied, new requests immediately receive `503 Too many requests`.

  rows={[

The health route currently returns HTTP `200` for all three values, so a monitor must
inspect the JSON `status` when warning or unhealthy should fail a check. Tune the limits
with [Configuration & operations](/docs/configuration#concurrency--load).
